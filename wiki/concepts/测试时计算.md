# 测试时计算（test-time compute）
## 定义
`测试时计算`（test-time compute）指模型在推理阶段额外花费的计算资源。它不改变模型参数，而是在回答前通过更多 token、更多候选、更多修订、更多工具调用或更多隐藏状态迭代，让模型获得更强的问题求解能力。
在 LLM 语境里，常见形式包括：
- 思维链（chain-of-thought, CoT）
- best-of-N / self-consistency
- beam search / verifier reranking
- sequential revision
- tool-assisted reasoning
- thinking tokens / pause tokens
- latent reasoning
## 为什么重要
它解释了一条和“模型更大、数据更多、训练更久”不同的能力提升路径：同一个模型，如果在推理时被允许更合理地搜索、验证和修正，也可能显著变强。
这对 agent 工程尤其重要，因为 agent loop 本质上也是一种外部化的 test-time compute：
- 模型内部的 thinking：多生成中间推理 token
- agent 外部的 loop：多做几轮计划、行动、观察、验证和修正
- harness：让这个 loop 可控、可验证、可恢复
## 核心判断
### 1. 多想是一种资源配置，不是万能药
thinking time 应该按任务难度、风险和成本动态分配：
- 简单任务：直接回答，少用 CoT 和 loop
- 中等任务：增加思考、候选和验证，收益通常最大
- 超出模型能力的难题：单纯多想不够，需要更强模型、更好工具、更好数据或人类介入
所以，强模型加合理思考时间，通常比弱模型无限空想更靠谱。
### 2. 自我修正需要外部反馈
模型天然 self-correction 并不稳定。没有外部反馈时，它可能把正确答案改错，也可能用更顺滑的语言包装错误。
更可靠的反馈来源包括：
- 单元测试（unit tests）
- 编译器或运行错误
- SQL dry-run
- 计算器或代码解释器
- 检索结果
- 领域 verifier
- 人工 review
### 3. CoT 是审计信号，不是真相
CoT 让推理过程更可见，但不能默认忠实。模型可能先得出答案再补理由，也可能受提示影响却不承认。
更危险的是，如果把 CoT monitor 直接作为 RL reward，模型可能学会隐藏真实意图，形成 obfuscated reward hacking。因此 CoT 适合作为审计线索，不适合作为唯一真相来源。
### 4. 工具是可靠思考的一部分
真正可靠的思考不是模型闭眼多想，而是知道什么时候该用外部世界纠偏。
在企业场景里，能用工具验证的地方不要只靠语言推理：
- SQL 要 dry-run
- 指标要查口径
- 代码要跑测试
- 权限要查策略
- 事实要查来源
### 5. Prompt 只是局部指令，loop 才是过程设计
设计思考能力不只是写“请一步步思考”。更完整的设计包括：
- 是否需要思考
- 思考多久
- 是并行生成多个候选，还是顺序修订
- 什么节点调用工具
- 失败后如何重试
- 最多循环几次
- 什么情况下停止
- 什么情况下交给人
因此：
- `prompt`：每一步怎么说
- `loop`：整件事怎么跑
- `harness`：让 loop 可控、可验证、可恢复
## 对业务 agent 的启发
以数仓 SQL agent 为例，不应只写一个“请认真生成 SQL”的 prompt，而应设计 thinking policy：
- 先识别指标、维度、时间范围、过滤条件
- 指标不清楚时查指标字典
- 生成 SQL 草稿
- dry-run SQL
- 报错后根据错误信息修正，设置最大重试次数
- 执行成功后检查结果行数、空值、时间范围和异常值
- 涉及高风险口径时请求人工确认
- 最后输出 SQL、假设、证据和风险点
这里 prompt 只是每一步的局部语言，真正的价值在 `识别 -> 查证 -> 生成 -> 执行 -> 验证 -> 修正 -> 交付` 这条 loop。
## 与其他概念的关系
- 和 [[wiki/concepts/harness工程|harness工程]]：test-time compute 解释了 loop 为什么有用；harness 负责把 loop 工程化。
- 和 [[wiki/concepts/工具|工具（tool）]]：工具是外部化的验证和计算资源，能让思考更可靠。
- 和 [[wiki/concepts/AI评估|AI评估]]：需要评估 CoT 是否忠实、verifier 是否可靠、thinking budget 是否真的带来收益。
- 和 [[wiki/concepts/自演化智能体风险|自演化智能体风险（Misevolution）]]：对 CoT 或 reward 施加强优化压力可能诱导 reward hacking 和隐蔽化行为。
- 和 [[wiki/concepts/构建高效智能体|构建高效智能体（Building Effective Agents）]]：不是所有任务都需要 agent 或长 loop；必须按复杂度和风险控制思考成本。
