## 核心理解

“记忆”不是单一功能。三份文档分别讨论用户个性化、项目协作规则和开发者持久存储；不能据此推断三者共享同一套底层数据，或模型权重发生了变化。

| 层次 | 文档描述的机制 | 主要关注点 |
|---|---|---|
| 用户产品 | chat 与 Cowork 共享记忆，对话中更新；用户可按主题查看、修改、删除 | 跨任务连续性、用户控制和敏感主题设置 |
| 编码协作 | 人写的 CLAUDE.md / AGENTS.md 与 Claude 自写的 auto memory 配合 | 长期规则与经验分工、文件作用域、加载条件 |

## 值得保留的事实

- 产品记忆默认不记录健康、信仰等敏感主题，用户可选择开启。组织默认开关不能一概而论：文章顶部更新特别说明了太平洋时间 2026-10-31 起新建的多数 Team / Enterprise 组织，覆盖了正文较早的笼统描述。见[产品更新](https://claude.com/resources/articles/claudes-memory-works-everywhere-and-you-decide-whats-in-it)。
- 指令文件描述应如何工作，自动记忆保存纠错、偏好等经验；两者都作为上下文使用，不能替代工具权限等强制控制。AGENTS.md 是否加载还受版本、已有 CLAUDE.md 和设置影响。见[编码文档](https://code.claude.com/docs/en/memory)。
- memory store 默认 `read_write`，也支持 `read_only`。读取不可信输入的智能体若被注入，可能把恶意内容写入长期记忆并影响后续会话。见[平台文档](https://platform.claude.com/docs/en/managed-agents/memory)。

## 版本与限制的核对

- PDF 中的 `::cite[...]` 是未解析的引用占位符；知识页改用可访问的官方链接，原始 PDF 保持不变。
- 按本次核对快照：每个 session 最多挂载8个 store，每个 store 最多10,000条 memory；PDF 另记单条100kB。容量属于版本化实现参数，接入前应重新核对。
- 变更生成不可变版本，但历史并非永久保留。官方说明历史通常保留30天，存活 memory 的近期版本有例外；恢复通过读取旧内容并重新写入，没有专用恢复端点。
- 删除当前 memory 不自动清掉其全部历史；`redact` 用于清除历史内容并保留审计轨迹。见[平台版本管理](https://platform.claude.com/docs/en/managed-agents/memory#audit-memory-changes)。

## 对现有知识库的影响

- 扩展 [[wiki/concepts/上下文工程|上下文工程]]：将“外部记忆”进一步分成规则、经验与参考知识，并明确读写治理。
- 呼应 [[wiki/concepts/自演化智能体风险|自演化智能体风险]]：一次污染可能跨 session 传播，持久化会放大错误的影响范围。
- 对 [[wiki/concepts/LLM Wiki|LLM Wiki]] 的启发：记住信息不等于形成可信知识，仍需来源、维护、纠错与用户授权。

## 实践建议（本库综合判断）

- 稳定协作约定放指令文件，临时进展与自动经验放独立记录，审核后的领域知识进入 wiki。
- 共享参考资料优先只读；按用户、项目和信任边界划分可写区域。
- 新记忆保留来源和时间，覆盖旧判断时说明原因；删除与回滚应考虑历史版本。
- 对本库而言，用户明确要求“加入知识库”才触发摄入；产品自动记忆的默认行为不构成本库自动写入的授权。
