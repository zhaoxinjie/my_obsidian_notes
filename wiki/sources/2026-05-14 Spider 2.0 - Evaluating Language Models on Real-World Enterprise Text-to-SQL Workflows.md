# 2026-05-14 Spider 2.0 - Evaluating Language Models on Real-World Enterprise Text-to-SQL Workflows
## 来源信息
- 原始路径: `raw/assets/SPIDER 2.0- EVALUATING LANGUAGE MODELS ON REAL-WORLD ENTERPRISE TEXT-TO-SQL WORKFLOWS.pdf`
- 标题: SPIDER 2.0: EVALUATING LANGUAGE MODELS ON REAL-WORLD ENTERPRISE TEXT-TO-SQL WORKFLOWS
- 作者: Fangyu Lei 等
- 发布日期: 2024-11-12
- 会议: ICLR 2025
- arXiv: 2411.07763
- 项目页: https://spider2-sql.github.io

## 摘要
这篇论文说明，真实企业里的 `text-to-SQL` 已经不是“给定 schema，生成一条 SQL”的问题，而是一个更接近 `SQL agent` 的工作流问题。Spider 2.0 不只要求模型生成 SQL，还要求它理解海量元数据（metadata）、查阅 SQL 方言文档（dialect docs）、利用项目代码库（codebase），并在执行反馈（execution feedback）下完成多步数据处理与分析任务。

## 关键要点
- Spider 2.0 包含 `632` 个真实企业级 `text-to-SQL workflow` 任务。
- 平均每个数据库有 `700+` 列，SQL 平均约 `148` token，复杂度远超 Spider 1.0 与 BIRD。
- 最强 `o1-preview` code agent 在 Spider 2.0 上只有 `17.0%`，远低于 Spider 1.0 的 `91.2%` 与 BIRD 的 `73.0%`。
- 真正难点不只是 SQL 语法，而是 `schema linking`、方言差异（dialect handling）、多步规划（workflow planning）、代码库利用、执行反馈闭环。
- 论文实质上在推动评估范式从 `text-to-SQL parser` 走向 `enterprise SQL agent`。

## 对知识库的影响
- 为知识库补上了一条更贴近企业落地的主线：数仓 `text-to-SQL` 不应只按“生成 SQL”建模，而应按“复杂数据工作流”建模。
- 它同时加强了 `AI评估`、`上下文工程`、`工具`、`harness工程` 这几条主线在企业场景下的交叉价值。
